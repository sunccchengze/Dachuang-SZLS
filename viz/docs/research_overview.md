## 1. 研究目标（申请书原文提炼 + 当前进展对齐）

### 1.1 申请书中的原始表述

> 风能的高效利用是实现双碳目标的关键……大型风电场中，机组间尾流干扰导致流场分布不均，传统调控方式难以精准匹配电网功率需求。本项目面向未来风电智能运维系统，尝试研究融合数据-物理驱动的风电流场智能感知与智能调控技术，通过构建风电场流场智能分析模型，精准捕捉流场分布特征与机组高效运行耦合关系；进而对风电机组的功率输出、转速、桨距角、偏航角等参数进行智能调控，实现电网需求与风电输出的精准匹配。

### 1.2 拆解成可考核的子目标

| # | 子目标 | 当前状态 | 负责人 |
|---|--------|----------|--------|
| A | 尾流场快速感知模型（代理模型）：给定风况+机组状态，快速预测流场/功率 | 神经网络已训练好，R²>0.998，但数据来自FLORIS而非高保真CFD | 厉今飞 |
| B | 物理规律在模型中的融合方式 | 当前仅通过输出层的求和约束实现了总功率一致性；PINN未引入 | 厉今飞/袁夫达 |
| C | 基于尾流感知的偏航优化：寻找最优偏航角组合以提升全场功率 | 已有FLORIS插值代理的优化求解器（2D网格搜索） | 洪祖名/孙承泽 |
| D | 功率需求跟踪控制：输入电网目标功率，输出偏航角组合 | 已有接口框架，等待真实神经网络模型接入 | 洪祖名 |
| E | 可视化系统：将上述链路以交互式方式呈现，供评审/运维人员审查 | Streamlit系统已有10个页面， dashboard.py新增总览面板 | 孙承泽 |

### 1.3 关键 ambiguity（需要团队确认）

- **最终要解决的核心问题到底是什么？** 是「功率提升XX%」、「控制响应时间小于XX ms」、还是「为运维平台提供可解释的决策依据」？这三类目标对模型精度要求、数据规模、验证方式完全不同。

## 2. 数据的合理性和普适性

### 2.1 数据来源

| 项目 | 内容 |
|------|------|
| 工具 | NREL FLORIS v4.6.6 |
| 尾流模型 | GCH（Gauss-Curl Hybrid）和 CC（Cumulative-Curl）两种，各自生成一套数据 |
| 风机 | NREL 5MW（额定功率5MW，转子直径126m，轮毂高90m） |
| 布局 | 3台风机沿X轴串列，间距378m（3倍直径） |
| 输入变量 | 风速(4~12 m/s, Δ=0.5)、风向(0~345°, Δ=15°)、湍流强度[0.06, 0.08, 0.10] |
| 样本数 | 1224条/模型（33风速 × 24风向 × 3湍流强度 - 含零功率剔除） |
| 输出变量 | 风机1/2/3功率(W) + 全场总功率(W) |

### 2.2 数据生成方式（袁夫达说明）

> 数据不是直接在github仓库上摘取，而是调用了floris中的两种基本内置函数模型（GCH尾流模型和CC尾流模型），基于多种风况生成对应的风机功率数据。

即：通过FLORIS的API批量调用两种尾流模型进行仿真，得到功率输出。这与直接下载别人加工好的数据是不同的——袁夫达写了数据生成脚本。

### 2.3 合理性存疑的地方（急需当面问）

1. **FLORIS本身的精度**：FLORIS是经验性的尾流模型（不是CFD），它的预测精度在什么量级？CC vs GCH差异有多大？（从测试指标看，神经网络对两种模型的拟合度都很高，说明数据本身很「干净」——这反而可能是因为FLORIS模型过于光滑，缺乏真实湍流的非线性。）

2. **训练用数据 vs 真实工况的差距**：
   - 真实海上风速分布是威布尔分布，4~12 m/s是否覆盖了关键风速区？
   - 实测风向变化是连续的，步长15°是否足够捕捉尾流偏转效应？
   - 湍流强度仅3个离散值[0.06, 0.08, 0.10]是否太少？

3. **零功率样本剔除**：厉今飞说「任意一个y标签为0的样本都删除」。这是否会导致模型在风速低于额定启动风速的工况下失效？（实际海上风电场低风速时段很长。）

4. **特征工程的充分性**：
   - 当前只有风速、风向、湍流强度3个输入（经过sin/cos编码后为6个特征）
   - 没有考虑：大气稳定度、风切变指数、海面粗糙度、浪致湍流、当先风机的尾流还没完全发展就进入下一台的情况（间距3倍直径时这种效应显著）

### 2.4 预处理与特征构建的记录

| 步骤 | 做了什么 | 原因 | 合理性评价 |
|------|----------|------|------------|
| 剔除y=0样本 | 训练集中去掉了任一风机功率为0的样本 | 避免网络学习无意义的零输出 | 会损失低风速数据，但避免了饱和区噪声。需说明舍入的代价 |
| 风向周期编码 | sin(θ), cos(θ), sin(2θ), cos(2θ) | 避免0°=360°的不连续，捕捉双峰尾流效应 | 标准做法，合理 |
| 输出归一化 | 除以额定功率(W)得到比例 | 加速训练收敛 | 合理 |
| 物理一致性约束 | farm_power = (t1+p2+p3)/3，固定权重求和层 | 保证预测满足能量守恒 | 简单有效，但没有考虑尾流损失模型 |

## 3. 神经网络架构及其合理性（针对1224条样本）

### 3.1 网络结构（厉今飞设计）

```
6个工程特征
  → Normalization (adapt to training data)
  → Dense(64, Swish, L2=1e-5)
  → Dense(128, Swish, L2=1e-5)
  → Dense(64, Swish, L2=1e-5)
  → Dense(3, Sigmoid)        # 3个风机功率比例
  → 固定求和层 [1/3, 1/3, 1/3]  # farm_power = 均值×3（即和）
  → 输出：[turbine_1_frac, turbine_2_frac, turbine_3_frac, farm_frac]
```

放大1000倍即为实际功率(W)。

### 3.2 参数量估算

- Input→Dense(64): 6×64 + 64 = 448
- Dense(64)→Dense(128): 64×128 + 128 = 8320
- Dense(128)→Dense(64): 128×64 + 64 = 8256
- Dense(64)→Dense(3): 64×3 + 3 = 195
- 总计 ≈ **17,219 参数**

样本数1224（有效），训练集854（CC）或840（GCH）。  
**参数/样本比 ≈ 17219/854 ≈ 20.2** —— 这个比值偏高，容易过拟合。好在用了L2正则化、EarlyStopping、ReduceLROnPlateau，且验证集R²依然很高，说明FLORIS数据太「规则」了。

### 3.3 激活函数选择

| 层 | 激活函数 | 选用原因（需要厉今飞确认） |
|----|----------|---------------------------|
| 隐藏层 | Swish (x·σ(x)) | 比ReLU平滑，避免神经元死亡；在中小型回归任务中常优于ReLU |
| 输出层(风机功率) | Sigmoid | 将输出限制在[0,1]，对应[0, 额定功率] |
| 输出层(总功率) | 线性(固定求和) | 保持物理一致性 |

**老师的问题（后续要问厉今飞）**：
- 为什么选Swish而不是ReLU、GELU、Tanh？有做过消融实验吗？
- Sigmoid输出层限制了单机功率≤额定功率，这在物理上是对的；但如果输入风速超过额定风速（当前最大12 m/s < 11.4 m/s额定风速，所以没问题），是否需要clip？
- 损失函数为什么选MSE而不是MAE或Huber？对于功率这种有软上限的数据，MSE会不会过度惩罚大功率区的误差？

### 4.3 初步观察（孙承泽视角，可商讨）

1. GCH模型的预测精度略优于CC模型（MAE~0.7% vs ~0.8%），但两者都在1%以内。这是否意味着CC模型本身的仿真数据波动更大（更接近真实湍流），导致神经网络更难拟合？还是CC模型生成的数据有某种系统性偏差？

2. turbine_2（中游）在两种模型下MAE都最高。原因可能是：中游风机同时受到上游尾流和下游湍流的双重影响，功率波动最大。

3. 目前所有讨论都是基于FLORIS仿真数据。**一旦替换为CFD或实测数据，精度会掉多少？** 这是整个项目成败的关键变量。袁夫达提到「在fluent跑出高保真数据之前，可以尝试通过优化函数来提高数据精度」，这个优化函数的方向和标准是什么？

## 5. 项目整体推进建议（李良星视角）

### 5.1 回归申请书，明确终点

申请书里写得很清楚：「数据驱动分析 + PINN + 基于PINN的启发式优化算法」。目前 Neural Network 部分 only 做了第一步（纯数据驱动的回归模型）。距离「物理信息神经网络」还有多远？

### 5.2 各组之间的接口

- **仿真组（田）** 应该提供什么格式的数据？目前README里写了`cases.csv`规范，但那是给FLORIS/插值模型用的。神经网络真正需要的输入是什么？如果将来要用PINN，输入是不是要包含网格化的流场数据而不仅仅是功率？
- **建模组（袁夫达）** 除了FLORIS数据，下一步是不是要跑Fluent/OpenFOAM？数据规模会从1224条变成多少？
- **AI组（厉今飞）** 当前模型的输入是3个标量，输出是4个标量。如果未来要预测整个流场（比如128×64的速度场），网络架构要怎么变？
- **优化控制组（洪）** 目前优化器用的是线性插值代理模型。神经网络模型 ready 后，优化器的接口只需要替换`surrogate_model.py`里的`predict_power`函数。洪是否已经准备好了优化算法（网格搜索、梯度优化、强化学习）？

### 5.3 物理规律的融合

目前仅在输出层做了求和约束。申请书里提到的PINN路线——是否要把Navier-Stokes方程、尾流守恒关系、功率曲线物理约束作为损失函数的附加项？具体要怎么做？
